# 服務交付 Pipeline

版本：2026-10-31。此為美國市場試點 SOP 草案，尚未對真實商家執行。

## 交付原則

一個商家窗口、一份修復清單、一套商品事實、一個可對帳的訂單中心。平台提供結帳與物流基礎設施，我們提供診斷、設定、資料修復、驗收與維護。

預設範圍：1 店、英文／美國、最多 100 可購買變體、2–3 個指定通路、1 套既有履約流程。多品牌、多國、搬站、換倉、客製結帳或歷史資料清理另估。商家自行決定商品價格、真實規格、退款政策與營運預算，我們可代整理並提供建議。

## 階段與驗收

時間是規劃假設，平台審核、索引更新、庫存入倉和商家回覆會影響日曆時間。約 24 小時直接工時的標準導入假設不含等待、搬站與新倉庫建置。

| 階段 | 具體工作 | 產出與驗收 | 責任與依賴 |
| --- | --- | --- | --- |
| 0. 售前篩選 | 確認產品、賣點、客戶、美國配送、既有平台、訂單量與預算 | 填 intake；不符合資格者說明可做與不可做的部分 | 我們訪談；owner 提供資訊 |
| 1. 付費抽樣診斷 | 抽 5–10 變體、6 個問題 × 2 個介面 × 1 次；檢查公開頁面與後台資格 | 約 12 次探索觀測；top 5 問題、證據、工作量、是否值得導入 | 約 4 小時假設；不宣稱完整曝光基準 |
| 2. 導入與資料盤點 | 匯出商品／政策／配送設定，確認資料權威來源與平台權限 | 完整變體清單、權限清單、資料缺口、可逆變更記錄 | 商家授權帳戶；我們核對 |
| 3. 完整基準 | 固定 30 問題、3 介面、各 3 次，保存原始回答與結帳路徑 | 270 次觀測，失敗／未觸發均保留；非品牌與品牌分開 | 大規模採樣需工具驗證成本；人工抽查 |
| 4. 商品與網站修復 | 分類、屬性、變體、政策、可抓取性、頁面與 schema、圖片／URL | 所有在範圍商品完成檢核；缺值有清單，關鍵錯誤清零或明確排除 | 商品主張由商家確認 |
| 5. 通路分發與准入 | Catalog／Merchant Center；選定 feed mapping 與同步；記錄審核進度 | 通路狀態截圖、接收／拒收結果、同步與告警；待審核獨立標記 | 平台資格由平台決定 |
| 6. 結帳驗收 | 商品／變體／價格／運費／折扣／稅費／付款／訂單通知 | 測試矩陣、訂單紀錄、失敗原因與 fallback；未能驗證就記未驗證 | 正式消費者通路與 sandbox 分開 |
| 7. 履約與售後 | 訂單路由、3PL／運單、追蹤回寫、RMA、退款與庫存 | 一次完整路徑；真實配送需低額且商家明確授權的測試 | 物流加值；倉庫與承運商執行實體工作 |
| 8. 上線與復測 | 重跑同一查詢組；核對變更、數據、訂單與商家權限 | before/after、限制、回滾點、未完成依賴清單 | 不因搜尋未上升就修改測試題美化 |
| 9. 月費維運 | feed／價格庫存／通路健康、固定曝光樣本、修復與月報 | 每月行動與結果、工時、成本；續約價值不足則調整服務 | 約 6 小時／月目標，超量另議 |

完整 270 次觀測是導入前後的設計目標，尚未證實能放進成本預算。先在第一家試點計時與核對工具可用性；若只能人工操作，縮小題組並清楚記錄樣本，或提高報價。不得省略重跑卻保留完整基準的說法。月費初期採 10 個固定非品牌題 × 2 個主力介面 × 3 次＝60 次觀測，完整題組按季或另案執行。

## 商品資料的標準與驗收

資料欄位分成三類，分別統計完成率，不能用描述文字填滿掩蓋缺少價格／庫存：

| 類別 | 欄位／檢核 | 規則 |
| --- | --- | --- |
| 可交易必需 | 穩定 item／variant ID、SKU、URL、圖片、價格／幣別、庫存／可購買性、目標市場 | 必須能對到實際可買變體；價格來源一致；測試的缺貨品不得可下單 |
| 推薦所需事實 | 品牌、類別、用途、尺寸／材質／容量／相容性、限制、GTIN／MPN（適用時） | 沒有的資料不編造；不適用與未知分開 |
| 商業政策 | 配送範圍、出貨／運送時效、退貨時限、費用、退貨地址、客服與保固 | 網頁、feed、知識庫與後台一致；以已核准政策為準 |

每欄保留來源、更新時間、負責系統、核准人與渠道 mapping。站內 ID、Google ID、外部 feed ID、WMS SKU 用對照表連接；不能靠商品名稱配對。上游改商品時，以增量比對與同步結果追蹤，不手動維護互相衝突的多份主檔。

試點的內部目標：在範圍內必需欄位 100% 通過、推薦相關適用欄位至少 95% 完整、抽查價格與庫存一致率 100%。這些是服務自訂驗收目標，**不是平台官方門檻**。欄位齊全不代表推薦率一定提高。

## 結帳／履約測試矩陣

每個可用通路至少涵蓋下列情境。各通路當下的限制以[研究來源](research/sources.md)及實際後台為準，不支援者設回商店購買或排除商品。

| 情境 | 應驗證的結果 |
| --- | --- |
| 一般商品與指定變體 | 收到的 SKU、數量、單價與訂單一致 |
| 缺貨／庫存剛變動 | 不接受不可履約商品；顯示新狀態或安全返回網店 |
| 支援／不支援的美國郵遞區號 | 提供正確運送選項或明確拒絕；不產生錯誤運費 |
| 折扣、免運門檻、稅費 | 由權威 checkout 計算；使用者確認金額與最終訂單相同 |
| 付款拒絕／額外驗證 | 不把失敗當付款完成；可恢復或轉回網站 |
| 連續點擊／網路 timeout／事件重送 | 不重複扣款或建立重複訂單；記錄可追查 ID |
| 取消與已交倉交界 | 狀態明確；不能取消時有客服處理路徑 |
| 部分出貨／部分退款／換貨 | 訂單、付款、庫存與追蹤對得上 |
| 退貨收到但未驗收 | 不提前回補可售庫存；退款依商家核准政策 |
| 通路故障與 app 被移除 | 告警、重試與人工佇列；保留原網店購買路徑 |

原生通路先確認平台提供的保障並驗收；只有自建 adapter 才自行實作簽章、冪等、重試、失敗佇列與事件對帳。測試成功不得推定另一個通路同樣成功。

## 維運與異常

工作流程：偵測 → 建工單 → 確認影響商品／通路 → 暫停錯誤資料或導回可用 checkout → 修復 → 重跑驗收 → 對帳與結案。

先設三類：P0 為錯價交易、重複訂單／扣款等立即需處置事件；P1 為同步失敗、庫存失真或通路拒收；P2 為曝光下降或內容改善。**這是分級，尚非承諾的 SLA。** 試點報價需訂美西服務時段、owner 緊急聯繫、可暫停的動作與退款權限；無人在值班時不宣稱 24/7 回應。

物流異常工單必須有外部供應商案件 ID、最後狀態、下一動作與負責人。商家帳戶由商家持有；服務退出時移交設定、欄位 mapping、未結工單與去識別化報表，撤銷我們的存取權。

## 成效指標與歸因

| 指標 | 定義 | 注意事項 |
| --- | --- | --- |
| 非品牌提及率 | 非品牌觀測中出現商家的次數／有效非品牌觀測次數 | 每平台獨立；同題重跑不是完全獨立樣本 |
| 自有網站引用率 | 引用商家自有 domain 的觀測次數／有效觀測次數 | 提及品牌與引用網站分開 |
| Shopping 觸發率 | 出現購物介面的觀測次數／支援該介面的有效購物觀測次數 | 未觸發是結果，不能當技術錯誤排除 |
| 商品卡出現率 | 出現商家目標商品的觀測次數／購物意圖有效觀測次數 | 另報在已觸發 shopping 中的比例，分母要明寫 |
| 商品資訊準確率 | 抽查正確的商品欄位數／抽查適用欄位數 | 價格、變體、庫存與配送分開 |
| 資料接收與健康 | 已接收商品比例、拒收原因、最後成功同步、資料過期時間 | 有後台證據；發送成功不等於平台接收 |
| 結帳成功率 | 成功完成測試情境／可支援且可執行的測試情境 | 另列未支援、待准入與技術失敗，不合併成零 |
| 訂單與貢獻 | 平台歸因或可辨識來源訂單、退款後淨額及變動成本 | referrer 缺失、跨裝置與站外 checkout 可能漏記 |
| 交付經濟 | 每客工時、工具分攤、工單數、維運成本與續約 | 與客戶成效同時決定是否擴張 |

技術錯誤（例如測試工具無法開啟平台）可標記無效，但要報原始樣本數、失敗數及原因。不能把沒有提到品牌記為無效。搜尋變化列為觀測關聯；若要估增量，配對未修改商品或分批上線，並記促銷、季節、價格和其他廣告變動。樣本小就報原始次數與範圍，不下統計顯著結論。

## 最小內部工具

第一階段只需要：商品匯入／欄位檢核、通路 mapping、觀測紀錄、變更清單、工單與月報。可以先用商家原生後台及簡單表格運作；平台 credentials 使用受控機密儲存，客戶資料與原始回答放在有適當權限的客戶工作區。

自動化順序：匯入與去重 → 必需欄位驗證 → 價格／庫存差異告警 → 固定測試與報表 → 通路 adapter。先把重複工作量量出來，再選工具，不為尚不存在的客戶先建完整多租戶系統。
